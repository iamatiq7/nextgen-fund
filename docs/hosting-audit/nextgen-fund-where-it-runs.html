প্রতিটি স্ক্রিপ্টের আউটপুট evidence/-এ টাইমস্ট্যাম্পসহ সেভ হয়। দুইবার (run a ও b) চালিয়ে হোস্ট, IP, TLS চেইন ও ক্যাশ-নোড কোড একই পাওয়া গেছে — অর্থাৎ ফল পুনরুৎপাদনযোগ্য।

১২. ঝুঁকি, সীমাবদ্ধতা ও হস্তান্তর

#পর্যবেক্ষণঝুঁকিসুপারিশ
১একই কনটেন্ট দুই হোস্টে (Firebase + GitHub Pages)বিভ্রান্তি, দুই ক্যাশ, SEOএকটি অফিসিয়াল হোস্ট ঠিক করুন; অন্যটি বন্ধ/রিডাইরেক্ট
২Soft-404 (সব পাথে 200)মনিটরিং/SEO-তে ভুল সিগন্যাল404 কনফিগ বা rewrite সীমিত করুন
৩GitHub Secret = প্রশাসনিক service-account keyফাঁস হলে পুরো প্রজেক্টে অ্যাডমিন প্রবেশশেয়ার না করলে ঠিক; সন্দেহ হলে key rotate করুন
৪repo পাবলিকসোর্স ও পাবলিক কনফিগ সবার দেখাগোপন তথ্য কখনো কমিট করবেন না
৫Firestore rules ডিফল্ট-ডিনাই— (ভালো)anonymous পড়া 403 — এটাই কাঙ্ক্ষিত; ঢিলা করবেন না
৬Firestore লোকেশন অজানাকমপ্লায়েন্স/লেটেন্সিconsole → Firestore → Location দেখে নোট করুন
৭Firebase-এ হোস্টিং origin রিজিয়নলেটেন্সি পরিকল্পনাMeasure: এজ ক্যাশ থেকে ঢাকার জন্য CCU-ই দিচ্ছে

হস্তান্তর চেকলিস্ট — কে কী করবে

  • মালিক: Firestore-এর Location নোট করুন (রিপোর্টের “অজানা” অংশ পূরণ হবে)
  • মালিক: কোন হোস্ট অফিসিয়াল (Firebase web.app নাকি GitHub Pages) ঠিক করুন
  • মালিক: service-account key rotate করবেন কি না ঠিক করুন
  • অপারেটর: ডিপ্লয়ের পর last-modified ও x-served-by মিলিয়ে দেখুন
  • যে কেউ: “পুনরুৎপাদনের ধাপ” চালিয়ে ফল মিলান; না মিললে প্রমাণ ফাইলসহ জানান

কখন আবার যাচাই করতে হবে

  • প্রতিটি ডিপ্লয়ের পর — ফাইল হ্যাশ ও last-modified বদলেছে কি
  • TLS মেয়াদ শেষের ~৭ দিন আগে (Firebase 2026-10-18 · Pages 2026-10-31) — অটো-রিনিউ হচ্ছে কি
  • GitHub Secrets / Billing / হোস্টিং প্ল্যান বদলালে
  • নতুন কাস্টম ডোমেইন যোগ হলে (DNS A/CNAME/TXT আবার যাচাই)

রোলব্যাক

এই অডিট কোনো কনফিগ, DNS, কোড বা ডেটা বদলায়নি — শুধু পড়া হয়েছে, তাই ফেরানোর কিছু নেই। ভবিষ্যতের জন্য:

# হোস্টিং কনটেন্ট আগের ভার্সনে
firebase hosting:rollback --project nextgen-fund-2040        # CLI থাকলে
# অথবা Firebase console → Hosting → Release history → Rollback
# অথবা GitHub-এ revert করে push (CI আবার ডিপ্লয় করবে)
git revert <commit> ; git push origin main
# Firestore ডেটা ফেরানো (ব্যাকআপ থাকলে)
node tools/db-reset.mjs --restore --from <backup>.json
