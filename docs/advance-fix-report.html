02মূল কারণ (Root cause)

ব্যালেন্স কোথাও “সংরক্ষিত” নয় — প্রতিবার পেমেন্ট লেজার থেকে computeBalance() চালিয়ে হিসাব হয়। পুরোনো কোডে দুটি আলাদা বালতি ছিল:

// আগে — assets/js/store.js:145-152  এবং  assets/js/firebase-adapter.js:113-120
if (p.status === 'verified') {
  if (p.type === 'due')     paidDue += amt;
  if (p.type === 'advance') advance += amt;   // শুধু "advance" ধরনের পেমেন্টই অগ্রিম
}
...
due:  Math.max(0, expected - paidDue - pendingDue),   // বিলের বেশি টাকা এখানে ০-তে ক্ল্যাম্প হয়ে হারিয়ে যায়
advance: advance                                       // due-payment-এর উদ্বৃত্ত কখনো এখানে আসে না
ঠিক কোথায় হারিয়ে যেত: সদস্যের দুইটি ৳1,000 পেমেন্ট দুটোই type: "due" হিসেবে জমা হয় → paidDue = 2,000। expected = 1,000। তাই due = max(0, 1,000 − 2,000) = 0 — ঠিক আছে। কিন্তু advance শুধু type === "advance" থেকে আসত, আর কোনো এমন পেমেন্ট ছিল না → advance = 0। ফলে ৳1,000 কোনো কার্ডেই দেখা যেত না। লেজারে টাকা ছিল (দুটি verified রো), শুধু হিসাবের বালতিতে ঠিকানা পেত না।

03চূড়ান্ত নিয়ম (locked spec)

expected = months(joinMonth→now) × monthlyDue paid = Σ verified (due + advance) advance = max(0, paid − expected) due = max(0, expected − paid − pending)

একটি বাক্যেই: প্রতিটি verified টাকা = ফান্ডে আসা টাকা; এখন পর্যন্ত বিলের বেশি অংশ = অগ্রিম। কোনো সঞ্চিত “advance” ফিল্ড নেই — তাই পুরোনো ডেটাও নিজে থেকে ঠিক হয়।
