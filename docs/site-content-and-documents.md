# সাইট কনটেন্ট কী, আর সদস্যদের ডকুমেন্ট কোথায় যাবে

## ১. "Site content" আসলে কী? রাখা দরকার কি?

হ্যাঁ, দরকার — তবে খুব কম। সাইটে দুই ধরনের তথ্য আছে:

**(ক) সদস্যদের দেওয়া তথ্য (এটা অটোমেটিক, আপনি কিছু লিখবেন না)**
- কে কত টাকা জমা দিয়েছে, কত বাকি, কত অগ্রিম (payments, users)
- মোট ফান্ড, মাসভিত্তিক হিসাব (fundTotals)
- নতুন সদস্যের আবেদন ও তার ডকুমেন্ট (registrations, Drive)
- নমিনি পরিবর্তনের অনুরোধ ও অনুমোদনের ইতিহাস (nomineeRequests, audit)

এগুলো ডেটাবেসেই থাকে; আপনি শুধু অ্যাডমিন প্যানেল থেকে দেখবেন, অনুমোদন দেবেন, বের করবেন।

**(খ) আপনি যেগুলো লিখবেন (site content — এটাই আসল "কনটেন্ট")**
অ্যাডমিন প্যানেল → Settings-এ যেগুলো আছে:
| কী | কেন দরকার | কত ঘন ঘন বদলাবেন |
| --- | --- | --- |
| ফান্ডের নাম | হেডার, রসিদ, শিরোনামে দেখায় | একবার |
| মাসিক শেয়ারের অঙ্ক | প্রতি মাসের বাকি হিসাব এর উপর দাঁড়ায় | বছরে একবার বা নীতিমালা বদলালে |
| পেমেন্ট নম্বর (bKash/Nagad/Rocket/Upay/Bank) | সদস্যরা ঠিক জায়গায় টাকা পাঠাবে; ভুল নম্বর মানে টাকা হারানো | নম্বর বদলালেই সাথে সাথে |
| পরের মিটিংয়ের তারিখ ও নোট | ড্যাশবোর্ডের সবচেয়ে দৃশ্যমান কার্ড | প্রতি মিটিংয়ের পর |
| ফান্ডের নোটিশ/ঘোষণা | মাসিক ঘোষণা, ছুটি, বিশেষ নির্দেশনা | দরকার অনুযায়ী |
| প্রয়োজনীয় ডকুমেন্টের তালিকা | নতুন সদস্য কী কী জমা দেবে | নীতিমালা বদলালে |

**সংক্ষেপে:** সাইটের "কনটেন্ট" মানে উপরের ৬টি ঘর — বাকি সব হিসাব অটোমেটিক। এটি রাখা দরকার, কারণ এই ছয়টিই সদস্যদের দেখানো একমাত্র স্থায়ী ঘোষণা; আর এগুলো একজনের (অ্যাডমিন) হাতেই থাকা উচিত।

## ২. সদস্যের ডকুমেন্ট → Google Drive (আপনার ২টি কাজ)

প্রতিটি নতুন সদস্যের আবেদনে চারটি ডকুমেন্ট লাগে:
`nid-front`, `nid-back`, `profile-picture`, `nominee-passport-photo` — সবগুলোই বাধ্যতামূলক।
ইউজারনেম ধরে Drive-এ ফোল্ডার হয় (যেমন `kazi.rafi`), ভেতরে ঠিক ওই চার নামে ফাইল জমা হয়;
আগের ফাইল থাকলে সেটি মুছে নতুনটি বসে (ডুপ্লিকেট জমে না)।

**চালু করতে যা লাগবে (আপনার অ্যাকাউন্ট, ৫ মিনিট):**
1. <https://script.google.com> → New project → `tools/drive-upload/Code.gs`-এর কোড পেস্ট করুন।
2. (ঐচ্ছিক) `PARENT_FOLDER_ID`-তে একটি ফোল্ডারের আইডি দিন, যাতে সদস্যদের ফোল্ডার ওই ফোল্ডারের ভেতরে তৈরি হয়।
3. **Deploy → New deployment → Web app** · *Execute as: me* · *Who has access: anyone* → Deploy →
   অনুমতি দিন (Drive ব্যবহারের সম্মতি) → **/exec URL কপি করুন**।
4. সাইটের `assets/js/firebase-config.js`-এর শেষে `window.NGF_DRIVE_ENDPOINT = '...'`-এ সেই URL বসান → ডিপ্লয়।
5. পরীক্ষা: একটি আবেদন Submit করে Drive-এ `NextGen Fund members/<username>/` ফোল্ডারে চারটি ফাইল দেখুন।

URL না বসানো থাকলে সাইট Firebase Storage-এ আপলোড করার চেষ্টা করে (কোটা লাগে) — কিন্তু ডকুমেন্ট হারায় না।


## ৩. যাচাই ও দুটি জরুরি কথা

**প্রমাণ:** `tools/drive-upload/drive-e2e-proof.txt` — একটি নকল (mock) Apps Script endpoint দিয়ে বাস্তব ব্রাউজারে পরীক্ষা:
৯/৯ চেক পাস। endpoint ঠিক যা পেয়েছে: ফোল্ডার `drive.test`, এবং ঠিক চারটি ফাইল —
`nid-front.jpg`, `nid-back.jpg`, `profile-picture.png`, `nominee-passport-photo.jpg` (সবই বৈধ base64, সঠিক mime), আর অ্যাপDrive-এর ফিরতি লিংক রেকর্ড করেছে। এই পরীক্ষা নিজে চালাতে:
`node tools/drive-upload/drive-e2e.mjs <repo> <out.txt>`

**১) CORS:** Apps Script অবশ্যই **Who has access: Anyone** দিয়ে ডিপ্লয় করতে হবে, নইলে ব্রাউজার ফাইল পাঠালেও উত্তর পড়তে পারবে না (পরীক্ষায় ঠিক এই কারণেই প্রথমে দুটি চেক আটকেছিল)। আপলোডে "Failed to fetch" এলে ডিপ্লয়মেন্টটি আবার Anyone দিয়ে করুন।

**২) endpoint বসানোর জায়গা:** অ্যাডমিন প্যানেল → **Settings → "সদস্যের ডকুমেন্ট (Google Drive)"** ঘরে /exec URL বসিয়ে Save করুন — কোড এডিট বা নতুন ডিপ্লয় লাগবে না। খালি রাখলে Firebase Storage-এ fallback করবে।
